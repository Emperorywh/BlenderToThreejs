# 资源接入与复现

## Web 接入

正式源码位于 `HeavenlyPalace/web/src`，开发时通过 `/palace-assets/` 读取本目录 `assets/`。
`pnpm build` 自动生成包含模型与贴图的 `web/dist/`，部署整个目录即可。

五个 GLB 按建筑、地形、植被、人物、瀑布拆分，使用 `GLTFLoader` 和 `MeshoptDecoder`。
保留 `EXT_mesh_gpu_instancing` 创建的 `InstancedMesh`，不要展开为数千个普通 Mesh。

全部 Web 数据采用米制与同一原点，Blender `(x,y,z)` 已转为 Web `(x,z,-y)`，不要再次居中或旋转。
相机世界/投影矩阵为列主序，可直接传给 `Matrix4.fromArray()`。固定 4:3 机位使用完整投影矩阵和逆矩阵。
殿内机位已更新为 `hall-view-v3`：中轴 28 mm、Shift X=0、Shift Y=0.19，四比三基准垂直 FOV 约 51.5°。镜头保持水平，竖向上移收进藻井；偏移已包含在矩阵中，不能再设置 filmOffset 或手动叠加俯仰角。网页读取相机记录中的 `composition_framing`，从三比二到 2.4:1 逐步等比收紧至 1.16 倍，并保持门口地坪投影位置；其余机位继续按视口扩幅。

构图参数、人物站位与实测比例见 [殿内构图](殿内构图.md)。`Space` 是应用本轮空间调整的首选入口，会同步建筑、相机与人物；`All`、`Quality`、`Hall` 重建时也接入同一空间与构图。`View` 仅用于现有建筑上的相机更新，并同步人物资源。实测月门在三比二下占画宽 37.82%，2.4:1 下占 27.42%；两个画幅均保留约 22.01% 的门口地坪前景。

Base Color 使用 sRGB，Normal/ORM 使用线性数据；ORM 的 R=1、G=粗糙度、B=金属度。
法线为 glTF +Y，并有 MikkTSpace 切线；柱纹使用 UV1，玉石使用 UV0。
原环境 JSON 区分远景云海、近岛云雾、五团入口遮檐云及瀑布水雾。当前网页由 `cloud-sea/layout.json` 接管远景与入口遮檐云：使用六排门外云浪、三圈山脊、右侧岩壁古松，以及按正式中轴机位居中的十四团入口薄云；岛边和瀑布水雾继续读取原布局。重建与核验见[云海制作与验收](云海制作与验收.md)。
瀑布材质 `WEB_Waterfall_Static_Preview` 保留几何，出水口、路径和流向可用于后续动态材质。

## 重新导出

主殿包含 `h01` 建筑样板，版本写入清单的 `main_hall_revision`；本轮空间版本另记为 `hall_space_revision: hall-space-v3`。主殿使用单层舒展庑殿顶、实体筒瓦与瓦当、螭吻脊饰、60 攒柱头及补间斗拱、朱漆金线额枋、分层藻井、白石柱及莲瓣柱础。最高层台基补充石栏与须弥腰线，两侧柱廊去除白模阶段的半高屏墙。

`scripts/refine_main_hall.py` 顶部的 `P` 集中控制屋面宽深、正脊高度、檐口高度、曲率和柱径。屋面、梁架与石构分别保存在 `04H_主殿样板_*` 集合，构件使用 `H01_` 前缀。重复生成会替换这些构件，柱径使用新旧比例计算，不重复叠加。

`scripts/hall_space.py` 在样板基准上统一调整梁架、柱网与月门：名义净高由 44 米提高到 54 米，原柱径系数 1.18 收为 1.05，中央开间由 60 米增加到 78 米。中央柱轴为 ±39 米，相邻柱轴为 ±64.5 米，外侧 ±90 米不变。月门改为半径 32 米、圆心标高 49 米的落地圆弧，地坪标高仍为 36 米，落地净宽约 58.48 米。柱身保持圆截面，藻井与木构整体抬高；原始网格和矩阵保留在工程中，支持重复调整。

保留现有材质与精修构件、只应用这轮空间比例时，优先运行以下命令。`Space` 会核验新门洞与柱网，同步相机，再按顺序更新 `architecture.glb` 和 `characters.glb`；其余三类 GLB 按摘要核对后继承，`Compress` 会跳过已经压缩的文件。

```powershell
# 应用层高、开间和落地月门，同时同步构图及人物，再压缩与核验。
# 所有命令均在后台运行，不启动浏览器或网页截图测试。
.\web-assets-v01\Export-WebAssets.ps1 -Stage Space
.\web-assets-v01\Export-WebAssets.ps1 -Stage Compress
.\web-assets-v01\Export-WebAssets.ps1 -Stage Verify
```

需要重新生成屋面、梁架或石构时，运行 `Hall`。该阶段同样应用当前空间与构图，依次导出建筑和人物资源：

```powershell
# 重建主殿并同步空间与机位，依次导出建筑和人物，再压缩并检查。
# 所有命令均在后台运行，不启动浏览器或网页截图测试。
.\web-assets-v01\Export-WebAssets.ps1 -Stage Hall
.\web-assets-v01\Export-WebAssets.ps1 -Stage Compress
.\web-assets-v01\Export-WebAssets.ps1 -Stage Verify
```

首次主殿精修前的工程与资源备份位于 `qa/before-hall-h01/`。本轮空间修改前的完整工程与资产备份位于 `qa/before-hall-space-v3/`，构图入口执行前的工程、相机与人物资源位于 `qa/before-hall-view-v3/`。`h01` 原始构建基准仍使用原柱网、44 米月门与 1.18 柱径系数，生成后统一应用 `hall-space-v3`；不要把构建基准当作最终交付尺寸。自然环境在生成前后核对内容摘要。

`scripts/review_main_hall.py` 检查有效网格、材质规格、月门通行以及斗拱与屋面净空，结果位于 `qa/main-hall-verification.json`。可选 `-- --render`、`-- --render --clay`、`-- --render --interior` 分别生成主殿外景、灰模与殿内离线预览，输出为 `qa/main-hall-*.png`。它们用于资产检查，网页交互、实时光照与帧率由用户手动验收。

`scripts/refine_hall_space.py -- --verify` 进一步检查实际圆门尺寸、落地净宽、24 根柱身的标高与柱头连接，并采样旧门洞范围以外的新开口，结果位于 `qa/hall-space-v3-verification.json`。`scripts/compose_hall_view.py -- --verify` 核对五种画幅、三进柱列、七条门内通视射线以及相机 JSON，结果位于 `qa/hall-view-v3-verification.json`。`Verify` 阶段会串行执行这些检查。

当前资源包含 `q02` 主体质量升级：主殿挑檐与屋架比例、入口通厚月门、彩枋斗拱、山崖侵蚀起伏和分层松冠。
岩石、白石、铺地、瓦面与木构使用 `q02_` 共享 PBR 贴图；主殿柱身继续使用原有独立浮雕法线。
网页启用了近岛静态投影阴影，均衡模式使用 2048 阴影贴图，高清模式使用 4096。

需要 Blender 5.2、Node.js/npm，原件位于上级 `stage1/HeavenlyPalace_Detail_v09.blend`。
入口会自动查找 PATH、`D:\app\blender` 及默认安装目录，也可传入 `-Blender` 指定程序路径。
在 HeavenlyPalace 根目录运行：

```powershell
# 重建副本、烘焙适配与基础导出。
# 修改程序材质时追加 -Rebake，普通重复导出会复用现有贴图。
.\web-assets-v01\Export-WebAssets.ps1 -Stage All
.\web-assets-v01\Export-WebAssets.ps1 -Stage Compress
.\web-assets-v01\Export-WebAssets.ps1 -Stage Verify
```

只修改 Web 副本时可先用 `-Stage Export`，随后压缩和核验。
将旧网页副本升级到当前主体质量时使用 `-Stage Quality`；该阶段包含实体检查及导出。
质量升级具有版本保护，重复执行不会叠加模型。修改生成参数后，使用 `-Stage All` 从原始 V9 重新生成。
`scripts/upgrade_quality.py` 控制全场基础升级，`scripts/quality_materials.py` 控制共享贴图，`scripts/refine_main_hall.py` 继续生成主殿样板；新增网格始终以米为单位。

`scripts/review_quality.py` 可在 Blender 后台中检查圆门贯通、当前空间版本的月门尺寸、UV、无效坐标和实际贴图引用。
追加 `-- --render` 可生成离线资产全景，追加 `-- --render --detail` 可生成主殿近景，输出位于 `qa/`。
这些是独立灯光下的 Blender 模型预览，不能替代网页中云海、交互与性能的人工验收。

首次压缩或核验时自动通过锁文件安装 `tooling` 依赖；这些依赖不纳入 Git。
脚本针对本 V9 的实际对象命名，不能视作任意 Blender 项目的通用转换器。

`qa/` 与日志是按需生成的导出中间数据，已被忽略，可随时清理。需要导出时会自动重建目录与必要审计。
导出只保留最终 GLB 引用的纹理；基础色不包含直接光照、高光或 AO。
导出后可运行 `web` 的 `pnpm build` 检查构建；四机位、材质与实时性能由用户在 `pnpm dev` 界面中自行验收。
