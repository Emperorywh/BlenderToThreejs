# 云顶天宫 · 第一阶段白模

## 当前统一方案

本项目已实际逐张查看 `references/` 四张原图。布局以 `01_overview.png` 为最高优先级；`02_front.png` 补充主殿立面和月门，`03_oblique.png` 补充纵深和侧桥关系，`04_waterfall_side.png` 补充侧台、古松与瀑布位置。使用本机已经验证过的 Blender 后台 Python 控制通道，版本为实际查询得到的 Blender 5.2.1 LTS；未安装插件或下载资产。

统一采用迎宾浮台 → 下段桥梯 → 中继浮台 → 上段天梯 → 主殿高台的路径。主殿两侧各一座月门侧台，再分别连接一座开敞小亭浮台。共七块平台、六段连接、三个月门开口（含主殿中央月门），主殿三层屋顶，小亭各两层屋顶。左右侧台略有前后错位，维持主轴秩序，同时保留总布局参考的侧向纵深。

米制坐标以迎宾台中心台面为原点，+Y 朝向主殿。所有尺寸、台面高差、柱网、屋顶曲率、树木位置、人形尺度、瀑布落差、光照和六个相机参数，均以构建时实际读取的 `scene_config.json` 为唯一数值来源。配置中明确这些是设计假设，并非从概念图精确测量所得。桥梯踏步的实际进深及坡度由配置推导，记录在 `output/build_report.json`。

主殿保留真实柱网和贯穿的中央月门。屋面采用有厚度的连续弧面、出檐、角部起翘和分层屋脊；本阶段不制作瓦片、斗拱和雕刻。平台台面、承托带和下收基座分别可选且封底。古松使用弯曲树干与分层扁冠；瀑布使用独立命名的封闭薄体占位，云海只有不参与渲染的辅助标记。

## 参考冲突的处理

- 四张图中的中继台宽度、天梯长度和迎宾台局部边界并不一致。采用主参考的连续中轴和两段抬升，统一为一块横向中继平台；没有根据每张图片另外生成场景。
- 正面图近似镜像对称，主参考和斜视图对左右月门、侧桥与小亭的遮挡和前后位置不同。保留同一组左右附属构件，以主参考建立连接顺序，其余图片补充可见构件，不增加远景仙岛与大型楼阁。
- 屋顶层叠在不同概念图中存在局部檐线数量和宽度变化。固定主殿三层可读的屋顶轮廓；其他图中的局部交叠、脊饰和细部附檐不分别扩展为额外楼层。
- 参考图的夸张透视、云海遮挡和画面裁切不能与结构检查图同时匹配。透视图统一显示核心场景及悬浮体量；顶视和侧视用于核对真实占地与高差，不作为像素匹配结果。
- 背面墙体、屋内支撑体、平台完整底面和下收截面属于补充设计；它们延续已选择的体量，不宣称是不可见区域的精确还原。

## 工程组织与运行

主入口为 `scripts/build_whitebox.py`，复用几何工具为 `scripts/whitebox_geometry.py`，渲染入口为 `scripts/render_whitebox.py`，结构检查为 `scripts/validate_whitebox.py`。它们只管理带 `TIANGONG_PHASE1` 标签的对象与数据；建筑、平台、桥梯、基座、栏杆、古松、瀑布、人形、相机和照明分别组织在专用集合。相同截面构件复用网格，主要建筑、屋面和每座桥梯保持独立可编辑。

活动场景是 `Tiangong_Whitebox`。原始启动场景 `Scene` 被保留在工程中，未参与任何验收渲染；这样在现有工程内重跑时也不会删除无关场景。保存前的旧版工程备份在 `output/backups/`。

在本项目根目录运行：

```powershell
# 使用现有 Blender 安装，在独立后台进程生成和保存可编辑工程。
# 重建只管理本任务对象，并自动备份已有交付工程。
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background --factory-startup --python-exit-code 1 --python scripts/build_whitebox.py

# 重新打开已经保存的工程，再输出固定的六个机位。
# 不改变建筑、几何或对象可见性，图片写入 output/previews。
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background output/tiangong_whitebox.blend --python-exit-code 1 --python scripts/render_whitebox.py

# 实际读取网格和桥台端点，检查封闭性、开口与参数一致性。
# 此检查补充人工看图，不代表视觉验收自动通过。
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background output/tiangong_whitebox.blend --python-exit-code 1 --python scripts/validate_whitebox.py
```

需要保留手动添加的工程内容时，在构建命令中用交付 `.blend` 替换 `--factory-startup`。任务脚本生成的对象会按配置重建，手动修改这些任务对象不会反向写回参数；重要修改应先更新配置或另存版本。

首版检查图位于 `output/review_initial/`，其中保留了首版配置和初步结构报告。修正检查图位于 `output/review_corrected/`。最终只以 `output/previews/` 和交付工程为验收对象；渲染清单记录源工程、配置和图片哈希，供核对来源。

首版结构检查已确认可渲染网格封闭且有正向体积、中央和左右月门真实贯通、六段桥梯端点与配置台面高度一致。边界射线在精确边线上会产生浮点漏检，已改为向台面内侧微移取样，并保留原始端点高度核对；最终报告要求十二个端点全部命中真实台面。

## 待用户确认与阶段边界

需要用户审核的主要选择是：中轴纵深与高差、主殿屋顶层叠和宽高关系、两侧附属建筑的留白，以及首版人物尺度下的整体宏大感。这些属于设计判断，不以无依据的还原百分比描述。

基座仍为干净的分层收分体，未复现概念图的盘龙雕刻与不规则岩壁；屋顶统一为简化庑殿式曲面，尚未区分概念图里局部歇山、附檐和脊饰的差异。古松没有松针，瀑布是实体占位，背面没有展开精细室内设计。为完整呈现核心场景与基座，正面图中主殿占画面比例小于裁切较紧的正面参考；没有改变模型比例来追求单张图的像素匹配。正交侧视中左右侧台和小亭自然重叠，所有对象仍保持相同可见性，结合顶视和左右斜视读取即可。

交付停止在第一阶段白模验收，不进入精细建模、金色材质、云雾、动画、GLB 导出或网页集成。
