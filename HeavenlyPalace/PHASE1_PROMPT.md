# 云顶天宫：第一阶段全场景白模

请使用已经验证可用的本地 Blender 控制通道，在当前项目中实际制作“云顶天宫”的全场景白模。不要只提供教程、方案或未执行的代码，不要重新安装插件或配置环境。

本轮只统一空间设计、搭建真实三维结构并渲染验收，不制作最终精细场景。

## 1. 先看图，明确参考优先级

实际逐张查看 references/ 中的四张图片，不要只读取文件名：
- 01_overview.png：总布局主参考，决定中轴线、主殿与浮台位置、天梯连接和前后高差。
- 02_front.png：主殿正面参考，补充立面宽高关系、屋顶层叠轮廓、柱廊节奏和中央月门比例。
- 03_oblique.png：补充整体纵深、建筑体量与桥台关系。
- 04_waterfall_side.png：补充侧面屋顶、侧台、基座厚度、古松与瀑布位置。

这些是存在局部不一致的概念图，不是精确的同一模型多视图。布局冲突以 01_overview 为准；其他图片只补充不冲突的信息。不要为匹配四张图创建四套场景。

将无法同时满足的主要差异和采用的方案简要记录在 DESIGN.md。图中未展示的背面与底部，可按已选定的体量做简化补全；明确标为补充设计，不宣称是精确还原。

## 2. 统一设计，然后直接执行

先确定一个连贯的核心布局：前景迎宾浮台 → 主轴桥梯 → 中继浮台 → 上升天梯 → 主殿高台；主殿两侧布置与主布局一致的月门、侧台、连接桥及亭台。

以鸟瞰图可见的核心建筑群为范围，固定各类构件的数量和连接关系。远处大量背景仙岛本轮不展开。保持中轴秩序、主殿主导地位和建筑间的留白，不擅自增加大型建筑。

使用米为单位，1 Blender 单位代表 1 米；以迎宾台中心为平面原点，其台面为 Z=0，+Y 指向主殿，X 为左右，Z 向上。

根据参考比例制定首版估算尺寸，不必逐项向我询问。把主殿宽深高、屋顶层数、柱间距、浮台尺寸与高差、桥梯宽度与长度、植物位置以及相机参数写入 scene_config.json，并由脚本读取。尺寸属于设计假设，不是从图片精确测量的结果。

DESIGN.md 只保留当前方案、参考冲突处理、检查结果与待解决项；数值以配置为准，不另建一套互相矛盾的参数。后续因白模检查而调整时，同步更新配置与说明。

## 3. 白模要做到的程度

完整搭建主殿、主殿高台、前景与中继浮台、两侧平台、桥梯、亭台、月门、柱廊、简化栏杆和悬浮基座。

白模不等于全部使用方盒。主殿必须有可识别的中式屋顶轮廓：合理的屋面弧度、出檐、飞檐起翘与层叠关系；暂不做瓦片、斗拱细节和装饰雕刻。月门必须有真实开口与厚度，柱廊有明确间距，台阶有基本踏步节奏。

平台需要厚度与完整底面，悬浮基座保留上宽下收和基本层次。桥梯端点应接到对应台面，不能悬空错接、穿进主殿或突然断开。悬浮建筑本轮不添加接地支撑。

古松用弯曲树干和分层扁平树冠占位，保留主要姿态与分布，不制作松针。瀑布只用单独命名的简化几何占位，保留出水口和下落方向，不做流体模拟。云海高度用不参与渲染的辅助对象标记，不用云雾遮挡结构。

加入少量约 1.75 米高的人形占位作为尺度参照；这是选定的设计尺度，不是对参考人物身高的测量。

本轮不做贴图、金色材质、盘龙浮雕、精细绿植、复杂水体、体积云、月亮背景、动画、GLB 导出或网页集成。

## 4. 工程与执行约束

优先采用可重跑的 Blender Python 构建/渲染脚本，沿用现有可用工具。依据本地已安装 Blender 版本选择支持的 API，不猜测版本。

把建筑、桥梯、基座、植物占位、瀑布占位、尺度参照和相机分别组织到清楚命名的集合。主要对象可单独选择、修改；重复构件采用可复用方式，不合并成一个无法调整的大网格。

脚本只管理本任务生成的对象，重跑不得重复叠加场景或删除无关内容。只在当前项目范围写入文件，修改已有工程前备份，不覆盖参考图，不清空用户其他场景。未经许可不下载资产或安装软件。

## 5. 输出同一模型的六个验收视图

使用中性背景、柔和照明和少量灰白哑光材质，让轮廓、厚度与遮挡关系清楚可见；不要过曝，也不要用强逆光、雾、景深、反射或后期特效掩盖问题。

创建并保存六个相机，输出长边约 1600 像素的 PNG：
- front.png：沿主轴的正面透视，尽量接近正面参考的观看方向。
- left.png：左前方斜视。
- right.png：右前方斜视。
- overview.png：高位斜俯视，尽量接近总布局主参考。
- top_ortho.png：正交顶视，检查占地与连接。
- side_ortho.png：正交侧视，检查台阶坡度、体量和高差。

前四张是透视展示图，后两张是结构检查图，不要把正交图强行当作透视参考的像素匹配结果。

所有视图必须来自同一个已保存的 .blend、同一套几何和同一套对象可见性。不得按机位移动建筑、隐藏错误构件或使用参考图作为渲染背景/贴片冒充模型。初次匹配好机位后固定参数，以修改结构为主，不能靠极端焦距掩盖比例错误。

## 6. 实际渲染、检查、修正

先生成完整首版白模并保存，再渲染上述视图，实际打开渲染图片，对照主参考检查主殿轮廓、屋顶比例、中轴纵深、平台高差、侧台位置和桥梯连接。

优先修正最明显的体量与连接问题；发现问题时至少完成一轮“修改 → 重新渲染 → 再检查”，不要进入精细装饰阶段。记录仍然存在的差异，不用无依据的百分比声称还原成功。

最终将同一工程重新打开后输出六张最终验收图，确保图片与交付工程一致，并保存相机与场景设置。

若当前工具无法实际查看参考图或渲染图，应如实报告具体阻塞及已完成内容，不能声称已完成视觉验收。除缺图、权限或执行失败等真实阻塞外，完成首版过程中不必反复等待我确认估算尺寸。

## 7. 交付与停止点

在项目中交付：
- output/tiangong_whitebox.blend：可编辑的全场景白模与六个相机。
- scripts/：实际使用的构建和渲染脚本，主入口为 build_whitebox.py。
- scene_config.json：构建脚本实际读取的设计参数。
- output/previews/：六张最终验收图。
- DESIGN.md：当前设计、运行方式、已完成检查及尚未解决的问题。

最终回复给出真实文件路径、预览位置与待确认的主要问题。只有脚本运行成功不代表验收通过。完成这一阶段后停止，等待我审核白模，不自动开始精细建模。
